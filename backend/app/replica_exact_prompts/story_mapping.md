# Allocate the complete reference story before writing any screen

Use the ordered source_sequence observations and resolved_facts. Map every source
unit once, in order, before any target page is designed. Reference facts are not
current-product facts. Preserve the observed argument order, opening function,
evidence obligations and transitions; do not impose a hero/pain/feature template.

For each entry assign target_role, approved target_fact_ids, a specific translation,
information_gain, relation_to_previous, next_unit_id and handoff. Use null for the
last next_unit_id. Explain repetition_mode and repetition_reason from the actual
source. Use concrete roles of at least eight characters, not short category labels.
Same-theme promise, pain, mechanism, evidence and usage can legitimately reuse a
fact. Preserve source-intended repetition. Never allocate every available fact
exactly once or invent differences merely to avoid repeated keywords.

First retain the persuasive job with truthful product-native evidence. A mechanism
screen explains why, a result screen states a supported outcome, and a proof
screen supports its actual conclusion. Composition ratios cannot establish efficacy.
If a cross-role substitution is necessary, explain the changed evidentiary scope
and coherent neighbouring handoffs; do not repeat an existing ingredient screen.
When no honest mapped argument is possible, put the concrete missing information
in evidence_gap. Otherwise use an empty evidence_gap. Never invent a fact to fill it.

For correction use previous_mapping and prior_story_review, changing only
repair_unit_ids. Preserve every other entry verbatim. Repair affected allocations
and handoffs from the actual findings; never merely ask a reviewer to pass.
