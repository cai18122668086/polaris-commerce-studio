# 视频空间本地体验版

页面布局参照必火数字人工作台，品牌与配色使用极光商绘。视频空间使用独立外壳，不依赖电商图片的 `AppShell`。原站桌面与移动导航仅对服务端确认允许的灰度身份提供「视频创作」入口，在新标签页打开；后续可将入口指向单独子域名。

## 页面

- `/video-studio`：首页、快捷功能卡、公共数字人。
- `/video-studio/create`：文本/音频驱动、数字人、声音、文案编辑、文案助手与作品。
- `/video-studio/avatars`：公共模特、定制形象与克隆表单。
- `/video-studio/voices`：系统声音、专属声音与克隆表单。
- `/video-studio/library`：当前账号与工作区的服务端文案库。
- `/video-studio/works`：服务端演示任务记录及静态预览。
- `/video-studio/editing`：后续剪辑入口。

## 当前行为

草稿、产品事实、参考来源、文案版本与演示任务保存到服务端，按当前用户和工作区隔离；同账号换浏览器可恢复。编辑器可选择/新建项目、查看与恢复文案历史，创建演示任务时保存不可变确认稿。localStorage 仅保留按身份/工作区隔离的未提交内容恢复，以及 `polaris-video-studio-demo-v1` 旧记录的显式导入；旧记录不删除。选择的文件不会上传，服务端仅保留本地媒体关联信息。音频驱动可以本地播放，刷新页面后需重新选择音频。系统声音目前仅为选项演示，试听使用浏览器 speechSynthesis，不代表供应商音色。

「生成视频」会先展示确认弹窗，用户明确点击「创建演示任务」后保存服务端演示记录与确认版本；不发送供应商请求、不扣费、不输出视频文件。文案助手和二创只提供本地示例。示例形象沿用项目自有展示图片。

## 后续接口边界

项目持久化已接入 `features/video-studio/project-session.ts` 与 `backend/app/video_studio_routes.py`；所有视频业务路由复用灰度/工作区门禁，写入采用版本检查与持久幂等请求。后续继续替换本地生成示例，保持页面结构：

- 链接采集：提交参考视频 URL，返回异步任务 ID，轮询取回原文与来源信息；在「文案二创 → 视频链接提取」接入。
- 文案改写：提交原文、产品事实和改写要求，返回可编辑文案与版本；在二创和右侧文案助手接入。
- 声音与数字人：分别提供资产列表、克隆任务、TTS 试听/正式音频、数字人视频任务；页面只使用内部资产 ID 与任务 ID。
- 作品：草稿、版本、确认稿和演示任务已持久化；音频/原片文件、真实任务状态和失败原因待后续接入。未知提交结果先查询，避免重复付费提交。
- 剪辑：后续接收确认文案、正式音频、口播原片、产品资料；保留「智能剪辑」入口。

当前沿用原站认证边界，并通过 `VideoStudioGate` 在挂载工作台前调用 `GET /api/v1/video-studio/access`。入口和全部子路由默认拒绝；授权逻辑集中在后端 `VideoStudioDependency`，未来业务 API 必须复用该依赖，再校验资源归属。退出、换账号、失败/超时均撤销前端允许状态，不使用浏览器邮箱或本地数据授权。开发账号没有自动放行。

完整验证证据、真实登录未验证部分和后续六阶段计划见 `docs/video-studio-handoff-2026-11-04.md`。拆到子域名时，需要另外明确共享登录、跨域和对象存储策略；此版本未修改任何线上域名或部署配置。
