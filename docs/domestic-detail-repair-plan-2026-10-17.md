## 职责与拟定模块

保持现有单体部署，拟在 `backend/app/domestic_detail/` 建立功能内模块；这是目录设计，尚未创建实现。

| 职责/文件 | 输入与输出 | 必须保持的边界 |
|---|---|---|
| facts.py | 用户商品图/确认事实/证据引用 -> 身份与主张账本 | 字符串 token 作为完整语义；不从风格参考或生成图增加商品事实 |
| plans.py | 事实账本 -> 模块职责/接缝/双屏顺序/审批版本 | 一套权威方案；嵌套与根层不能各自维护冲突版本；批准指纹绑定输入及契约 |
| contracts.py | 带来源的原生方案 -> Harness 契约与定位错误 | 无损转换主张处置和原因；缺失/未知值报错；不把要求当观察、不补乐观真值 |
| generation.py | 已批准版本 + 固定请求签名 -> 成组画布/切片/恢复状态 | 绑定源码、Skill、方案、素材、供应商请求与产物；明确已失败与结果未知；有界恢复 |
| review.py | 原始观察 + 像素哈希 -> 逐屏、接缝、全页结论与残差 | 保存原始审核回复；计划文案不能替代 OCR 或像素观察；未知不算通过 |
| delivery.py | 文件证据 + 质量状态 -> 展示/下载契约 | 技术完成、待人工复核、带残差、质量通过分别表达，不把文件齐全标为画面合格 |

公共执行器继续负责队列、租约、取消、幂等和计费；公共供应商网关管理传输与用量。事实补全、详情审核判定和双屏职责不再新增到大型 xinghe_agent.py / execution.py 中。

## 分步提交

1. 导出最小必要的真实失败方案/状态，脱敏后保留原始哈希、脱敏规则及样本哈希；不导出完整生产数据库或无关用户资产。原失败任务不重跑、不改状态。
2. 固定转换层输入输出、错误和费用/请求边界作为回放基线。先抽离无行为变化的适配模块，再用单独提交修复 DEFERRED 原因丢失。合法原因原样保留；未知原因继续严格拒绝；非 DEFERRED 按其契约处理，重复标准化稳定。
3. 分别修正事实 token、审批版本/嵌套权威、逐屏职责与组内/组间接缝引用；每项用真实样本或明确构造的边界样本验证。不能顺手改变主图、跨境、复刻和局部改图策略。
4. 独立提交恢复/幂等绑定，再独立提交观察证据保真、细粒度视觉门槛和最终交付状态。成功候选复用必须验证绑定；未知生成结果停止自动补发，防止重复计费。
5. 先验证真实失败样本通过严格预检，再在隔离栈中创建新的测试任务做真实生成，逐屏、成组、全页验收；最后准备发布提案。
