# 视频后台恢复运行说明

独立视频 API 的生命周期启动扫描器；`POLARIS_VIDEO_BACKGROUND_RECOVERY_ENABLED`
默认关闭，只在执行追加迁移 `20261107_0041` 后为 video-api 开启。

默认每 15 秒扫描到期任务，最多两个后台工作线程。请求触发的正常执行和后台
恢复共用 `video_generation_runs` 数据库租约：120 秒有效期，每 40 秒续租。
有效租约不会被另一个实例抢占；失去所有权的旧线程不能写入后续检查点。

登记每轮只读找回窗口结束后，业务任务仍保留。退避和执行次数持久化，按
15、30、60、120、240、300 秒继续查询，进程重启不会清空等待计划。
重启后的运行中任务需要原租约失效且心跳过期，随后自动接管并复用原材料。
已知编号的原/备用视频任务、已完成结果的下载、可恢复上传也进入自动续接。

付费提交之前持久保存阶段与登记/路由意图；恢复不会重发已不确定的 TTS、
H3、登记或口型 POST。模型登记只能按精确任务名称找回；已知视频 task_id
只能查询原任务；本地已保存的配音可以复用。没有编号、没有可信文件且上游
没有查询依据的付费结果保留待核对，不把重启视为重新付费的授权。
等待形象预览确认和已经明确失败的生成也不会被扫描器重新提交。

原渠道明确失败后的备用路由仍按既有规则执行：每个渠道只提交一次，实际
计费和失败退款由供应商决定。扫描与恢复不承诺上游失败任务自动退款。

回归覆盖：窗口外自动找回、持久退避、重启接管、真实 FastAPI 启停、两个
实例争抢、人工继续与后台并发、租约失效隔离、停机后旧响应迟到、未知付费
提交保护、已知任务继续查询、SQLite 实际迁移和 PostgreSQL DDL。
