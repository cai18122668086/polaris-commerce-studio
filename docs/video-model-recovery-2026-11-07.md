# 模型登记超时恢复

2026-11-07 的任务 `3644e19d-06bc-4eca-9ceb-98788549fc92` 在北京时间
14:29:21 提交完整动作模型，60 秒后响应未知。上游于 14:30:25 实际登记了
模型 `951`；本站没有拿到响应，未进入对口型生成。

形象登记与完整动作登记共用以下恢复逻辑：

- 单次登记请求等待上限 180 秒，连接上限仍为 15 秒。上游自己的网关仍可能
  提前返回 504，因此延长本地等待不能代替找回。
- POST 前持久保存已提交标记；请求超时、5xx、响应无法解析或缺少模型 ID
  时，只读取当前账号的模型列表，最多查询 90 秒，每次 GET 上限 15 秒。
- 仅接回名称精确等于原任务 UUID 名称的唯一、启用、私有视频模型。
  上游登记会复制素材并改变 URL，因此不以 URL 相等判断登记是否成功。
  同名多条、公共、停用、名称近似或 ID 无效都不会自动采用。
- 查询窗口内找到即继续原任务；仍不确定时显示等待继续处理，并允许继续
  查询。旧版 `unknown` 的两个模型登记阶段也可继续，历史阶段记录证明已
  提交，恢复不会再次 POST 登记。
- 成功回执先落库，再写业务阶段，避免在两次保存之间重启导致重复登记。
  原配音、已上传动作、其他付费任务均复用；对口型未知提交仍禁止重试。

只需更新视频 API，不需要数据库迁移或前端构建。生产恢复需先确认该任务
精确名称只有模型 `951` 一条，再走正常排队和工作流，让新逻辑自动接回。
恢复过程应限制禁止 TTS、重新上传和登记，仅允许一次使用 `951` 的对口型
提交，随后跟进原供应商任务到成片或明确状态。

回归覆盖网关 504、传输超时、非 JSON、缺少 ID、延迟可见、查询故障、重复
查询、旧任务、保存后重启、另一类形象登记及确定拒绝。部署记录与生产恢复
结果存放仓库外，凭据与私有素材不进入源码。
