# 一键复刻：产品流程与发布说明

用户入口为 `/style-replica`，主导航名称为「一键复刻」。首页用该入口承接原参考图创作卡片的位置，保持六卡布局；原「一键模仿」工作台、任务和菜单入口继续保留。

## 用户流程

1. 上传自己的商品图片。
2. 粘贴淘宝/天猫、1688 或京东商品链接，拉取后按主图、详情图、SKU 图勾选；也可以直接上传风格参考图。
3. 设置目标平台、语言、图片比例；商品事实和要求可选填。
4. 分析后查看每张图片的方案，可补充要求，确认后生成。
5. 在当前页面查看、放大、下载、单张重试；刷新或从历史记录打开后可继续查看。

不提供 16 类模块选择，也不提供模型、画质选择。平台、语言和比例采用统一的自定义下拉菜单。每张选中的参考图对应一张生成图片，最多选择 20 张。

## 数据与生成

| 来源 | Just One API | 控制台成功请求单价 |
| --- | --- | --- |
| 淘宝/天猫 | `/api/taobao/get-item-detail/v6` | ¥0.25 |
| 1688 | `/api/1688/get-item-detail/v1` | ¥0.10 |
| 京东 | `/api/jd/get-item-detail/v3` | ¥0.40 |

报价查验于 2026-10-21，按供应商控制台账户价格记录；只有成功的数据请求计费，试用请求由供应商执行。同工作区、同平台、同商品在同一北京时间日期内复用成功缓存。勾选多张图片不会重复查询商品 API。

接口依据：[使用说明](https://docs.justoneapi.com/zh/usage)、[淘宝/天猫 V6](https://docs.justoneapi.com/zh/api/taobao-and-tmall/product-details-v6)、[账户控制台](https://dashboard.justoneapi.com/)。

数据接口不自动回退到自建浏览器。拼多多目前可作为输出目标，来源图片可手动上传；此版本不承诺拼多多链接采集。

本功能分析与生图均固定使用 Tengli，文本与图片分别使用对应的服务器凭证，关闭本功能的供应商故障转移。图片生成沿用已有 `reference_remix` 任务、配额、用量、素材与任务记录。

参考复刻采用已锁定的 `reference-visual-reverse-remix` Skill：产品图提供身份和商品事实，参考图提供构图、光影与视觉策略。分析与执行保持相同的图片角色和顺序。

## 一致性与资源边界

- `replica_documents` 保存商品缓存、分析进度、方案、确认指纹及子任务关联；只允许访问所属工作区。
- 商品导入仅接受本次接口返回的 CDN 图片，复用既有上传配额、图片校验和幂等机制。
- 分析每次只加载当前参考图；单个 API 进程最多并发两项分析。
- 已完成的分析结果在重试时复用。新的分析尝试使用独立标识，过期的排队尝试不能覆盖新结果。
- 确认方案后按图片创建独立任务；重复确认、重复重试不会创建额外的替代任务。
- 提交前检查既有活动任务上限；容量不足保留方案，不开始半批任务。异常造成的部分提交保留进度，可继续提交剩余图片。
- 进程重启后未完成的分析会在超时后显示为可重试；生成任务沿用既有数据库 Outbox/Celery 恢复机制。
- 单图使用素材附件接口下载，不调用仅面向套图的 ZIP 接口。

## 发布边界

采用当前生产代码基线上的独立发布分支，保持其他对话的工作区和分支不变。

需要新增 `replica-api`、`replica-worker`，新任务使用 `one_click_replica` 队列。现有 dispatcher 只增加该队列的路由；Caddy 只增加 `/api/v1/workspaces/*/replica/*` 的反向代理。前端更新工作台和导航。

详情 API、详情 Worker 及其模型、环境、任务与状态不属于本次替换范围。发布前检查当前容器与配置摘要，完成备份/恢复预检；变更时校验基线，避免覆盖同时发生的发布。

数据库迁移仅新增表。应用回滚保留已导入图片和方案，不删除该表。
